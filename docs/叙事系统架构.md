# 叙事系统架构

## 架构定位

本系统目前采用**静态叙事**：剧情在离线烘焙阶段就定稿，运行时只读。这里的“静态”指的是**剧情图**结构不可变，即对话、选项之间的连接关系和内容不可变，不能在运行时动态地增删改。但分支玩法不受影响，选择分支、条件分支和随机分支等仍然存在。同时，运行时的剧情走向来自玩家的选择和变量状态，而不是来自修改剧情结构或文本本身。总而言之，剧情图是静态的、固定的，但玩家在图上怎么走是动态的：  

- 不能改剧情结构和文案：运行时不能新增、删除、修改剧情节点和文案。
- 可以改运行时状态：运行时玩家的选择可以改变剧情的变量或状态，从而影响条件判断和分支走向，但剧情图本身不变。这些变量或状态可被存档。
- 暂不能动态生成剧情：不支持运行时程序化生成剧情或动态拼接节点，如未来需要，可作为独立扩展。
- 只能整包替换：版本更新/热更时，以整包或整章为单位替换烘焙产物并重新加载，不能对运行中的剧情图做局部增删改。

## 架构设计

1. 策划或编剧使用【固定格式的 Excel】或【自定义叙事脚本，暂定名 Huaben（话本），使用 `.hb` 文件】进行文本剧情编辑。
2. 将 Excel 导出的 CSV（UTF-8）或自定义叙事脚本 Huaben **离线烘焙**成同一套烘焙产物。
3. 烘焙产物的逻辑结构统一为边集数组模型（nodes + edges）。序列化文件可选 JSON、SQLite、binary。binary 比较特殊，可以选择存为边集数组，也可以直接存为 CSR。
4. 运行时加载烘焙产物，统一构建/使用可选邻接表/字典（便于以后增加增删改能力）或压缩稀疏行 (Compressed Sparse Row, CSR)。
5. 提供叙事编辑器的查看编辑功能，可将剧情以图结构节点进行展示，也可以进行修改。将 Excel 或自定义叙事脚本读取为邻接表保证编辑交互流畅。修改后的剧情仍然可以导出为 Excel 或自定义叙事脚本。

| 分工 | 读 | 写 | 职责 |
| :---- | :---- | :---- | :---- |
| 策划/编剧 | N/A | Excel / Huaben | 唯一可编辑源 |
| 编辑器 | Excel / Huaben | Excel / Huaben | 查看、编辑编辑器节点图，并写回源文件 |
| 烘焙 | CSV / Huaben | JSON / SQLite / binary | 校验、规范化、产物 |
| 运行时 | JSON / SQLite / binary | 变量、状态存档 | 只读剧情图 |

### 运行时

``` text
 策划编辑                离线烘焙                          运行时
┌───────────────┐ bake ┌───────────────────────────┐ load ┌──────────────┐
│ Excel (.xlsx) │ ───> │ 边集数组                   │ ───> │ 邻接表/字典   │
│ Huaben (.hb)  │      │ JSON / SQLite / binary    │      │ CSR          │
└───────────────┘      └───────────────────────────┘      └──────────────┘
```
