# 对话系统表格设计

## 1. 数据表

### 1.1 批次划分

| 批次 | 表 | 状态 |
|---|---|---|
| **① 现在做** | `chapters` `nodes` `edges` `characters` | 必须填 |
| ② 第二批 | `variables` `conditions` `effects` | 建空表占位 |
| ③ 第三批 | `scenes` | 建空表占位 |

**各表作用**

| 表 | 作用域 | 作用 |
|---|---|---|
| `nodes` | 章节 | 剧情节点：台词、旁白、分支汇合点、跳转、结束 |
| `edges` | 章节 | 节点的出边，定义推进与分支，CSR 的唯一数据源 |
| `scenes` | 章节 | 章内片段的索引与入口，用于定位与按段加载 |
| `variables` | **全局** | 对话系统依赖的变量声明（名字、类型、说明），供条件表达式校验 |
| `conditions` | **全局** | 可复用的条件表达式，供选项的显示 / 可用判断 |
| `chapters` | **全局** | 章节清单：入口节点、下一章、解锁条件 |
| `characters` | **全局** | 角色表：立绘、配色、语音前缀等跨章共用资源 |
| `effects` | **全局** | 可复用的指令组：改变量、发道具、播音效 |

**三层划分**

| 层 | 表 | 所在 |
|---|---|---|
| **内容** | `nodes` `edges` `scenes` | 章节，一章一个工作簿 |
| **规则** | `variables` `conditions` | 全局，`global/` |
| **资源** | `chapters` `characters` `effects` | 全局，`global/` |

- **内容层**（3 张）：跟着章节走。随剧情增长而增加，几十章就是几十份工作簿，各自提交、互不冲突。
- **规则层**（2 张）：变量是规则的词汇表，条件是规则的判断部分。只依赖彼此，集中在 `global/` 目录。
- **资源层**（3 张）：被别处引用的实体——章节清单、角色、指令组。跨章共用，改一处全局生效。

判定原则一句话：**随章节变化 → 内容层，全局共用 → 规则层（判断逻辑）或资源层（被引用的实体）。**

### 1.2 `chapters`（全局表，一章一行）

| 列 | 类型 | 必填 | 批次 | 说明 |
|---|---|---|---|---|
| `chapter_id` | text PRIMARY KEY | ✅ | ① | 稳定 ID，如 `ch01`，与各章工作簿对应 |
| `chapter_title` | text | ✅ | ① | 章节标题，直接写在这里 |
| `entry_node` | Foreign Key -> nodes | ✅ | ① | 该章从哪个节点开始 |
| `next_chapter_id` | Foreign Key -> chapters | ✅ | ① | 下一章，最后一章留空（NULL）表示结束 |
| `unlock_if` | Foreign Key -> conditions | | ② | 解锁条件，留空（NULL）表示默认解锁 |

### 1.3 `characters`（全局表）

| 列 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `speaker_id` | text PRIMARY KEY | ✅ | 稳定 ID，格式 `spk_{三位序号}_{昵称}`，如 `spk_001_lin`；节点的 `speaker_id` 引用它 |
| `speaker_name` | text | ✅ | 角色显示名，直接写在这里 |
| `portrait_default` | text | | 默认立绘的资源 ID |

### 1.4 `nodes` 剧情节点

| 列 | 类型 | 必填 | 批次 | 说明 |
|---|---|---|---|---|
| `idx` | int PRIMARY KEY | ✅ | ① | 整数行号主键 |
| `node_id` | text UNIQUE | ✅ | ① | 稳定 ID，如 `ch01_0001`|
| `type` | enum | ✅ | ① | **决定后续节点**：它规定这个节点需要几条出边，以及运行时怎么处理。取值见下表 |
| `speaker_id` | Foreign Key -> characters | | ① | 角色 ID，旁白留空（NULL） |
| `zh_cn` | text | | ① | 中文文案，`line` / `narration` / `choice` 必填 |
| `en_us` | text | | ① | 英文文案 |
| `note` | text | | ① | 策划备注，不导出 |
| `pos_x` | int | | ① | 可视化坐标，节点图编辑器里的横坐标，不导出 |
| `pos_y` | int | | ① | 可视化坐标，节点图编辑器里的纵坐标，不导出 |

* `pos_x` / `pos_y` 只服务于可视化编辑器，无需手填，由编辑器写入。

> 演出相关功能 `stage` 暂缓，之后补充。它表示节点进入时的演出设置，需要游戏层先有对应的表现接口，所以不放进第一批。可以有背景音乐、立绘、音效、镜头、动画等。

**`type` 的语义**

`type` 是节点唯一的“行为开关”：它决定这个节点要连几个后续节点（0 条、1 条还是多条），也决定运行时是显示文字、等玩家选择、还是直接跳走。

| type | 出边数 | 运行时行为 |
|---|---|---|
| `line` | 1 | 显示台词，等玩家点继续 → 走唯一出边 |
| `narration` | 1 | 旁白，同上（无 speaker_id） |
| `choice` | ≥1 | 列出所有选项，等玩家选 |
| `random` | ≥1 | 随机选择一条出边 |
| `jump` | 1 | 不显示文本内容，不演出，直接跳 |
| `event` | 1 | 不显示文本内容，只有演出 |
| `end` | 0 | 本片段结束，无后续内容 |

### 1.5 `edges` 出边

| 列 | 类型 | 必填 | 批次 | 说明 |
|---|---|---|---|---|
| `idx` | int PRIMARY KEY | ✅ | ① | 整数行号主键 |
| `from_node` | Foreign Key -> nodes | ✅ | ① | 起始节点 id |
| `to_node` | Foreign Key -> nodes | ✅ | ① | 目标节点 id |
| `seq` | int | ✅ | ① | 选项显示顺序 |
| `once` | bool | | ① | 作为选项被选中过一次后，指向它的选项不再出现（仅本次会话） |
| `visible_if` | Foreign Key -> conditions | | ② | **不满足就不显示** |
| `enabled_if` | Foreign Key -> conditions | | ② | **不满足就灰显不可点** |

* 选项文本存在目标节点上，`edges` 不另存文案。
* `once` 只保证**本次会话内**不重复。若要"永久只出现一次"，属于存档语义，得让游戏侧用 flag 实现。

### 1.6 `variables` 变量声明（批次 ②，全局表）

| 列 | 说明 |
|---|---|
| `var_name` | PRIMARY KEY |
| `type` | `int` / `bool` / `float` |
| `desc` | 给游戏团队看的说明 |

### 1.7 `conditions` 条件（批次 ②，全局表）

| 列 | 说明 |
|---|---|
| `condition_id` | PRIMARY KEY |
| `expr` | 受限 DSL：`affection_lin >= 30 && flag_met_lin && !flag_route_locked` |
| `desc` | 自然语言说明，给人看 |

```
c_aff_lin_ge30        好感度 ≥ 30
c_flag_met_lin        已见过琳
c_item_key_granted    已获得钥匙
```

### 1.8 `effects` 指令（批次 ②，全局表）

| 列 | 说明 |
|---|---|
| `effect_id` | PRIMARY KEY，一组指令的集合 |
| `seq` | 组内执行顺序 |
| `op` | `var_add` `flag_set` `item_add` `unlock` `audio` `custom` |
| `target` | 变量名 / 道具 ID / 音效名 |
| `value` | 值 |

### 1.9 `scenes`（批次 ③，章节表）

| 列 | 说明 |
|---|---|
| `scene_id` | PRIMARY KEY |
| `entry_node` | 片段入口节点 |
| `bgm_default` | 该片段默认 BGM |

完全属于章内结构（这一章有哪几个片段、各自从哪进），跨章没有意义，所以留在章节工作簿里。第一批可以先用 `chapters.entry_node` 顶替。

## 2. 导出器约定（xlsx → csv）

1. 一次导出**全部** sheet，不允许按需选表（漏表是最常见的翻车方式）
2. sheet 名 → `{表名}.csv`，表头必须与 `schema.json` 列名完全一致：**缺列报错，多列警告**
3. 编码 **UTF-8 无 BOM**。带 BOM 时 Excel 打开 csv 不乱码，但解析器会把 `\ufeff` 读进第一列名，变成"列 node_id 不存在"，极难排查
4. 所有单元格按**文本原样**写出，不做数字/日期推断
5. 空单元格 → 空字符串（不写 `null`、不写 `NaN`）
6. 输出 `csv/_manifest.json` 记录 `xlsx_sha256` / `csv_sha256` / `exported_at`
7. **按最后一个非空行截断**。模板把数据区预置了 1000 行的单元格格式（为了让 ID 列保持文本），直接按 `max_row` 遍历会导出一堆空行——整行全空就跳过

**唯一允许的导出方式是这个工具**，禁止手工"另存为 CSV"。CI 每次构建重新跑一遍导出——这样"csv 比 xlsx 旧"在物理上不可能发生。

> 顺带说：Excel 里的下拉验证只是**源头方便**，不是保障。csv 可能被手改或被脚本生成，所以 bake 必须独立做全量校验，两边不共享代码。

## 3. 运行时（C#）

```csharp
public sealed class DialogueGraph
{
    public readonly string[] Ids;
    public readonly int[] RowPtr;        // [N+1]
    public readonly int[] ColIdx;        // [E]
    public readonly int[] EdgeType;      // [E]
    public readonly bool[] NodeOnce;     // [N]

    readonly Dictionary<string, int> _index;

    public int IndexOf(string nodeId) => _index[nodeId];

    /// 取出该节点的所有后继，**零分配**
    public ReadOnlySpan<int> Successors(int node)
        => new ReadOnlySpan<int>(ColIdx, RowPtr[node], RowPtr[node + 1] - RowPtr[node]);

    public int OutDegree(int node) => RowPtr[node + 1] - RowPtr[node];   // O(1)
}

public sealed class DialogueRunner
{
    readonly DialogueGraph _graph;
    readonly IDialogueState _state;
    readonly IDialogueCommandSink _sink;
    readonly HashSet<int> _visited = new();   // 进过的节点，只为 once，不落盘

    int _current;

    public string CurrentId => _graph.Ids[_current];

    public void Start(string nodeId) => _current = _graph.IndexOf(nodeId);

    /// 进入节点：触发指令（批次 ② 才有）
    /// 返回 true 表示需要玩家操作（line 等点击、choice 等选择）
    public bool Enter() { /* … */ }

    /// 当前节点可选项（已过滤 once 节点和条件）
    public int CollectOptions(List<int> outEdges) { /* … */ }

    public void Choose(int edgeIndex) { /* 记录 to_node、走 to_node */ }

    /// 线性推进：唯一出边
    public void Advance() { /* … */ }
}
```

要点：

- **加载完就不可变**，对外只暴露只读属性和 `ReadOnlySpan`。CSR 一旦被改，`row_ptr` 和 `col_idx` 立刻不自洽
- `Successors` 返回 `ReadOnlySpan` 而不是数组——不产生 GC，这对移动端很关键
- `_visited` 只活在这个对象里，`Runner` 被丢弃就没了，符合"不做存档"
- **换用 `ch01.bin` 时只换 loader**：`LoadJson` / `LoadBinary` 吐出的是同一个 `DialogueGraph`，`DialogueRunner` 和业务层一行不改
